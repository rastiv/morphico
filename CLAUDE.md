# morphico

Public library (MIT, npm + jsDelivr), **written in TypeScript**, of morphing line-art icons: states of an icon morph by interpolating SVG `path` data. First release: digits 0–9 in five styles — `round` (default), `square`, `condensed`, `slim`, `handwritten`. Later: semantic sets (weather, on/off, eye, …).

## Hard rules
- **TypeScript everywhere** (library, preview page, tools). Only erasable syntax (`erasableSyntaxOnly`: no enums, namespaces, parameter properties) so Node and the dev server can strip types. Type-only imports as `import type`; relative imports with the `.ts` extension.
- **Descriptive names.** No cryptic short names (`lerp2`, `d`, `a`, `n`, `u`, `k`…): name what the thing is (`interpolatePoint`, `digit`, `path`, `breakpoints`, `startSegment`). Minification happens at build/CDN time.
- **No runtime dependencies.** The published package depends on nothing. Dev dependencies allowed: **only** `typescript` and `@types/node` (agreed 2026-10-25). No linter (Biome was tried and rejected as unneeded complexity), no bundlers, no other tools (not even `npx serve`).
- Python is **not** installed on this machine; Node v24 is.
- **No SVG files as source.** Source of truth = TS geometry (`strokes`) + tuning (`pairLayouts`, `spins`, `alternativeStrokes`) in `src/sets/`. Icon sets: **only Lucide** (user's choice 2026-10-26, for consistency), converted once by `tools/import-lucide.ts` into TS; that TS is the source. Keep Lucide's resting look (shapes, round) — only the morphs are ours — but scaled by 16/18 around 12,12, line width too (2 → 1.78), so icons get the digits' room (16 units, y 4…20; user's choice 2026-10-26): `src/sets/lucide.ts` (`fromLucide`, `lucideLength`, `LUCIDE_STROKE_WIDTH`) — write Lucide coordinates in the set and convert. Lines are centred on the shape (no inside stroke alignment: user said keep it as is). No brand/logo icons.
- **Icon licenses:** only own drawings or MIT/ISC sources. Lucide (ISC, parts from Feather MIT): `LICENSE-lucide` (verbatim Lucide LICENSE, in package `files`), both notices (ISC + Feather MIT, copied from LICENSE-lucide) in full in the dist banner (build.ts; `/*!` survives minifiers), package.json `"license": "MIT AND ISC"` (2026-10-28), README note. No CC BY sources.
- The user is not a designer: Claude drafts geometry, the user judges by eye.

## The morphing contract
Within a set every state's path is `M x y` + **exactly `segmentCount` cubic segments**. Same structure ⇒ any two states interpolate number by number.
- `strokes` = one continuous line per state, in writing order. Arcs are split into ≤ 90° cubics (handle = 4/3·tan(θ/4)·r), lines become cubics with controls at 1/3, 2/3.
- `defaultBreakpoints` spreads the segments over the strokes by length (arcs ≥ 1 segment per 90°). `segmentCount` must cover the state with the most strokes.
- The default pairing (segment i ↔ segment i) is bad for many pairs, so each pair can lay out each side differently **without changing how it looks** (`pairLayouts[state][otherState]`: `startSegment` for closed loops, `reversed`, `breakpoints` along the strokes, `tracing` = alternative strokes, `rotation`). `spins[from][to]` = morph by rotating around 12,12 while blending.
- Breakpoint rules: a segment never spans two strokes; arc segments ≤ 90° (a 180° single cubic is ~1px off at 360px).
- Cost metric (tools): sum of squared differences of all numbers (not comparable between sets). A guide only — the user's visual rating wins.

## Lessons from the first sets (archived, redrawn from scratch now)
- Tricks that helped: one continuous stroke per digit (merge subpaths; go up a stem and back down over it; draw a stub bar out and back); closed loops (0, 8) can start anywhere (`startSegment`); an 8 can be traced in different orders with the same look (`tracing`: both loops clockwise, or in the order of the 3); a 9 drawn as exactly a 6 turned 180° makes 6↔9 a pure spin; 8 is 180°-symmetric (`rotation`).
- Hard pairs: shapes whose arcs open on opposite sides (2→6, 3→6); digits that use every segment leave no room for re-layout. More segments = more freedom (8 was limiting; 12–16 worked better).
- Workflow: user rates transitions (Good / Midd / Bad) → `tools/check.ts` for non-Good pairs → add `pairLayouts` entries (leave Good pairs untouched) → `tools/verify.ts` → user re-checks. Look for symmetries first. Run `check.ts` with the closed shape second (only the second gets start segments). Alternative tracings aren't searched automatically.

## Drawing a piece (PairLayout.draw, 2026-10-27)
- `wipe: 'left' | 'right'` (2026-10-27): like draw, but the piece is revealed behind a vertical edge moving across x 2…22 (same edge for every wiped piece of a morph); the visible part must be one stretch of the path → trace the piece to start where the edge reaches it last. `slide: true` (with wipe): the piece moves in with the edge from the box side (part outside the box hidden), leading side at the edge; the edge range of every wipe in that morph = box side … the (first) sliding piece's leading side at rest (`wipeRange`), so it starts just outside the box; other sliding pieces move along with it.
- `draw: true` (or a share 0…1 of the morph: erase at the start, draw in at the end; or a window `[start, end]` for staggering, erasing runs it in reverse) on the state where a piece is absent: `shapeForPair` gives it the other side's piece shrunk to its start point; `drawnPieces` + `withDrawnPieces` (geometry.ts) replace that piece in every frame by `trimPiece(present piece, progress)` — the first part of it along its length (rest shrunk to the pen's point), erased with `1 − progress` in reverse. Used by morph.ts and the preview stage (only from a settled shape; interrupted morphs just interpolate). `toPathData` leaves out pieces shrunk to a single point (round caps would show a dot); verify.ts skips them too.

## Pieces (multi-part icons, 2026-10-26)
- A set is its first piece; `morePieces: PieceSet[]` adds pieces (each = `strokes` / `alternativeStrokes` / `pairLayouts`, same `segmentCount`). Shape = path numbers of all pieces one after another (`pieceLengthOf`, `splitPieces`); `toPathData(path, pieceLength)` writes one `M…C…` per piece. Interpolation, spins, scaling work unchanged on the whole list.
- A state with fewer parts than the set has pieces repeats a part in the extra piece (drawn exactly on top → invisible); a morph then separates the copies. Tune each piece with `check.ts --piece=N`.
- `strokeWidth`: number = grid units (scales with the icon), string = CSS length (`'2px'`, `'0.1rem'`; user's request 2026-10-26) → set as `style.strokeWidth` on the svg + `vector-effect: non-scaling-stroke` on every stroked child (`createStrokedElement`; vector-effect is not inherited). Text dots = very short round-capped lines (`M12 y h0.001`, width 1.2 × stroke via `calc()` for CSS lengths) — tiny circles with thick strokes render as rings in Chromium. Text baseline uses the set's own width when the width is a CSS length. Preview: "Width in: grid units | px".
- Style options (2026-10-26, user: "library options too"): `strokeWidth`, `lineCap`, `lineJoin`, `fill` (svg.ts `StyleOptions`, icon + text); `roundness` (icon; 0 = sharp … 1 = own Lucide radii = maximum, user's choice — the radii differ per icon, play 2 / pause 1 / stop 2; sets with `withRoundness`, built from `roundedPolygon` — always line + arc per corner, radius 0 = arc shrunk to the corner point, so pair layouts stay valid; derived sets cached in `resolveIconSet`). Line join only shows on sharp corners: the preview disables it for icons unless roundness is 0. `toPathData` closes closed pieces with `Z` and writes them from the first segment with length (zero-length first segment → wrong closing join in browsers); icons have `overflow: visible` (sharp tips pass the 24 box).

## Library plan (agreed 2026-10-25)
- **API:** Layer 1 `icon(el, opts)` → `.to(state)`; Layer 2 `text(el, opts)` → `.set('04:59')` (only changed characters morph, "empty" digit state); Layer 3 `clip(el, opts)` (2026-10-29); `countdown()` maybe later as a separate file. No custom elements. `destroy()` for frameworks. `to()`/`set()` return a Promise **and** accept `onEnd`; interrupted morphs resolve (e.g. `{ interrupted: true }`), never hang.
- **Text cells (agreed 2026-10-25):** characters reuse the same 24×24 path data; only the `viewBox` is narrowed to a cell (`viewBox="12-w/2 3 w 18"`, svg width = w·size/18, so no squashing). `text()` options: `cellWidth` (default from the set, round = 10 with spacing 4 — chosen by the user), `spacing` (also via CSS variable e.g. `--morphico-spacing`), colon cell ≈ 5 with dots at the 8's circle centres (y 7.6 / 15.6). Later maybe `figures: 'tabular' | 'proportional'` (tabular default — clocks must not jiggle). The preview page has a text line to try this.
- **Requirements:** CSS inheritance (`currentColor`, em sizing); accessibility (`prefers-reduced-motion` → jump, `aria-label` kept in sync); SSR-safe; size budget 5–10 KB gzipped; one shared rAF loop.
- **Semver:** patch = nicer transitions/fixes, minor = new sets/options, major = API change or changed resting look of an icon. Keep `CHANGELOG.md` updated.
- **Git:** work on `main` until 1.0.0; after that branch → PR → merge. The demo site is a separate React/TS repo using the published package.
